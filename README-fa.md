## مرزیار چیست؟

**مرزیار** نسخه تکامل‌یافته و متمرکز بر سیستم نمایندگی برای **مرزدار** و **مرزبان** است.

مرزیار تمامی قابلیت‌های رابط کاربری **مرزدار** را همراه با مدیریت بومی و غیرقابل دور زدن نمایندگان و زیرساخت پرسرعت شبکه بر پایه Rust ارائه می‌دهد، درحالی‌که **عدم دستکاری دیتابیس** و **سازگاری دوطرفه کامل** را تضمین می‌کند:

1. **سقف تعداد کاربران نماینده**: تعیین دقیق حداکثر تعداد اکانت‌های مجاز برای هر نماینده.
2. **سهمیه ترافیک و مهار اورسل (Oversell)**:
   - **سقف مصرف یکپارچه**: در تمام حالت‌ها، مجموع ترافیک مصرفی (`ترافیک فعال + ریست‌ها و حذف‌های قبلی`) هرگز نمی‌تواند از `traffic_limit` نماینده فراتر رود.
   - **حالت سخت‌گیرانه (بدون اورسل)**: علاوه بر مصرف واقعی، جمع سقف ترافیک‌های تعیین‌شده برای کاربران (`∑ user.data_limit ≤ traffic_limit`) نیز کنترل می‌شود.
   - **حالت با امکان اورسل**: برداشتن محدودیت تخصیص؛ نماینده می‌تواند بدون محدودیت پلن بفروشد تا زمانی که مصرف واقعی او به سقف سهمیه برسد.
   - **حسابداری غیرقابل دور زدن**: نمایندگان نمی‌توانند با ریست کردن یا حذف اکانت‌ها سهمیه را دور بزنند؛ ترافیک‌های گذشته در تاریخچه انباشته می‌شود.
3. **ماشین وضعیت قطع خودکار (Locked State Machine)**:
   - با اتمام سهمیه نماینده، تمام کاربران فعال او به وضعیت `locked` رفته و اتصال آن‌ها در هسته Xray قطع می‌شود (بدون تغییر در جداول اصلی دیتابیس).
   - با شارژ یا ریست سهمیه توسط ادمین کل (Sudo)، کاربران به صورت آنی و خودکار در هسته Xray وصل و آزاد می‌شوند.
4. **محدودسازی اینباندهای مجاز**: اختصاص اینباندهای خاص و ایزوله به هر نماینده (مثلاً فقط دسترسی به پروتکل VMess TCP).
5. **ویجت زنده در هدر پنل**: نمایش وضعیت باقی‌مانده سهمیه ترافیک و تعداد کاربران برای ادمین‌های لاگین‌شده.
6. **موتور سرور پرسرعت مبتنی بر Rust و کش حافظه‌ای**: بهره‌گیری از وب‌سرور Granian (موتور ناهمگام Tokio)، کش هوشمند رم برای لینک‌های اشتراک و ایندکس‌های مرکب دیتابیس برای حداقل‌سازی تأخیر پاسخ‌دهی.

## نصب و مهاجرت

### مهاجرت از مرزبان یا مرزدار

تنها کافی است نام ایمیج را در فایل `docker-compose.yml` تغییر دهید:

```yaml
services:  
  marzban:  
    image: mehrwizard/marzyar:latest
```

سپس دستور ری‌استارت را اجرا کنید:
```bash
marzban update
```

## مستندات رابط کاربری برنامه‌نویسی (API)

علاوه بر اندپوینت‌های استاندارد مرزبان، مرزیار دارای مجموعه‌ای از اندپوینت‌های اختصاصی تحت پیشوند `/api/marzyar` برای مدیریت سهمیه نمایندگان، سقف تعداد کاربران، حالت‌های اورسل، محدودسازی اینباندها و کاربران قفل‌شده است.

مستندات تعاملی Swagger/OpenAPI نیز مستقیماً از طریق آدرس `/docs` در دسترس است (در صورت تنظیم `DOCS=true`).

### احراز هویت
تمامی اندپوینت‌های مرزیار از سیستم احراز هویت توکن استاندارد مرزبان استفاده می‌کنند:
```http
Authorization: Bearer <access_token>
```
برای دریافت توکن دسترسی:
```bash
curl -X POST "https://your-panel-domain:8000/api/admin/token" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "username=admin&password=yourpassword"
```

### فهرست اندپوینت‌ها

| متد | مسیر (Endpoint) | سطح دسترسی | توضیحات |
| :--- | :--- | :--- | :--- |
| `GET` | `/api/marzyar/admins` | فقط Sudo | دریافت تنظیمات، محدودیت‌ها، مصرف سهمیه و وضعیت قفل برای تمام ادمین‌ها |
| `GET` | `/api/marzyar/admin/{admin_identifier}/settings` | فقط Sudo | دریافت تنظیمات و آمار مصرف زنده یک ادمین خاص |
| `PUT` | `/api/marzyar/admin/{admin_identifier}/settings` | فقط Sudo | ویرایش سقف کاربر، سهمیه ترافیک، حالت اورسل و اینباندهای مجاز نماینده |
| `POST` | `/api/marzyar/admin/{admin_identifier}/reset_quota` | فقط Sudo | ریست شمارنده مصرف ترافیک نماینده و باز کردن آنی کاربران قفل‌شده |
| `GET` | `/api/marzyar/my_limits` | تمامی ادمین‌ها | دریافت محدودیت‌ها، سهمیه باقی‌مانده و دسترسی‌های ادمین لاگین‌شده |
| `GET` | `/api/marzyar/locked_users` | تمامی ادمین‌ها | مشاهده لیست کاربران قفل‌شده به همراه علت و زمان قفل شدن |

👉 برای مشاهده ساختار کامل درخواست‌ها، پاسخ‌های JSON و نمونه کدهای curl، به [مستندات کامل API مرزیار](docs/api-fa.md) مراجعه کنید.

## بهبود عملکرد و بنچمارک‌های زنده عملیاتی

پروژه‌های **مرزدار** و **مرزیار** مجهز به بهینه‌سازی‌های زیرساختی عمیقی هستند که برای پنل‌های عملیاتی پرترافیک طراحی شده‌اند:

1. **موتور سرور وب مبتنی بر راست ([Granian](https://github.com/emmett-framework/granian))**: جایگزینی سرور پایتونی Uvicorn با موتور پرسرعت Granian با موتور ناهمگام Tokio و اتصالات C/PyO3 برای دستیابی به توان پاسخگویی بالا با مصرف بسیار کمتر پردازنده.
2. **کش حافظه‌ای پاسخ لینک‌های اشتراک (Response Cache)**: ذخیره‌سازی پاسخ‌های تولیدشده در حافظه رم با طول عمر ۳۰ ثانیه و ابطال خودکار آنی به محض تغییر وضعیت، حجم یا تنظیمات کاربر.
3. **ایندکس‌گذاری ترکیبی و استراتژیک دیتابیس**: افزودن ایندکس‌های مرکب کلیدی روی جداول پرترافیک (`users(online_at)`، `users(created_at)`، `node_user_usages(node_id, created_at)` و `node_usages(node_id, created_at)`).
4. **تاب‌آوری چرخه اتصال نودها و آمارگیری**: ایزوله‌سازی چرخه‌های همگام‌سازی نودها، اعمال مهلت زمانی (Timeout) بر فراخوانی‌های gRPC و مدیریت خطای بهینه.

### شاخص‌های کلیدی بهبود عملکرد:
- ⚡ **۸.۶ برابر پاسخ‌دهی سریع‌تر در میانه**: کاهش میانه (p50) تأخیر پاسخ اشتراک در مانیتورینگ زنده از ۴۶.۲۷ به ۵.۳۷ میلی‌ثانیه (۸۸.۴٪- کاهش تأخیر).
- 🚀 **۲۳.۳ برابر توان اشباع با کش حافظه**: ثبت **۷۷۵.۲ درخواست در ثانیه** (۷,۷۶۴ درخواست در ۱۰ ثانیه) در برابر **۳۳.۲ درخواست بر ثانیه** (۳۴۱ درخواست) زیر بار ۱۵ ورکر همزمان (۲,۲۳۵٪+ ظرفیت بیشتر با کش درون‌حافظه‌ای).
- ⚡ **۹۶.۱٪- کاهش تأخیر زیر بار سنگین**: کاهش میانگین تأخیر در بار متوالی از ۴۴۷.۶۶ به ۱۷.۵۳ میلی‌ثانیه (۲۵.۵ برابر پاسخ‌دهی سریع‌تر).
- 🗄️ **۳۱.۷٪ کاهش فشار بر دیتابیس MySQL**: مهار اوج مصرف پردازنده دیتابیس از ۵۳.۶۲٪ به ۳۶.۶۴٪ زیر بار پیوسته به کمک کش رم و ایندکس‌های مرکب.
- 🛡️ **۲۵.۶٪ مهار اسپایک‌های کندی**: کاهش شدیدترین جهش تأخیر از ۶۰۴.۳۶ به ۴۴۹.۶۳ میلی‌ثانیه در بار پیوسته.
